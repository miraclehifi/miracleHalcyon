# 按豆瓣用户批量导入标记

**US ID**: US-04
**所属分组**: media-shelf
**状态**: draft

---

## 1. User Story

**作为** 作者
**我想要** 填上我的豆瓣用户 ID、勾选要导入的类别（电影、剧集、书、漫画、游戏、桌游），先一键全量导入我在豆瓣标记过的条目，以后只同步新标记的部分
**以便于** 不用逐条粘贴链接，几百条历史标记一次到位；不想要的类别可以不导；之后的日常同步几秒完成，不用每次翻完全部历史

---

## 2. 验收标准

1. Given 我在后台书影音列表页
   When 我点"从豆瓣导入"
   Then 弹出导入面板：豆瓣用户 ID 输入框（说明"豆瓣个人主页 douban.com/people/**ID**/ 中的 ID"）；上次用过的 ID 自动带出（存在服务端，换设备也能带出）
   And "导入类别"六个勾选项（电影、剧集、书、漫画、游戏、桌游）每次打开都默认全部勾上；每项旁小字显示该类别在这个 ID 下的上次同步时间（如"10-23 21:30"），从没同步过显示"未同步"
   And 该 ID 的所有类别都从没完成过同步时，只有"全量导入"按钮；有类别完成过时，主按钮为"同步新标记"，旁边是次要的"全量导入"
   And 一个类别都没勾时提示"至少选择一个类别"，两个按钮都不可用

2. Given 我填了合法的豆瓣用户 ID，并勾选了要导入的类别
   When 我点"全量导入"
   Then 按影视、书、游戏的顺序，只导入勾选类别中"看过 / 读过 / 玩过"和"在看 / 在读 / 在玩"的全部标记，"想看 / 想读 / 想玩"不导入；一个类别都没勾的大类不请求；面板显示进度"影视 · 看过 120 / 614"

13. Given 我只勾选了部分类别（例如只勾"电影"）
    When 导入或同步完成
    Then 未勾选类别的标记不写入、不下载封面、不计入汇总；书影音里已有的未勾选类别的条目不被改动；未勾选类别的上次同步时间不变

3. Given 豆瓣上的一条标记
   When 它被导入
   Then 条目的分类（影视按电影 / 剧集区分，书带"漫画"标签归漫画，游戏类型含"桌游"归桌游）、标题、作者 / 导演 / 开发商、年份、豆瓣链接按单条识别的规则填写；状态、评分（1–5 星，未评分为空）、标记日期、短评取自豆瓣标记

4. Given 导入的条目分类不是游戏且豆瓣有封面
   When 它被导入
   Then 封面由服务端下载存入 R2；下载失败时条目照常导入、无封面，计入汇总里的"封面失败"

5. Given 导入的条目是游戏
   When 它被导入
   Then 不下载豆瓣封面（游戏封面只用 IGDB 链接）；平台取我在豆瓣标记的平台（PS5 / PS4 / Switch / Switch 2 / PC→Steam），标记里没有能对应的平台时新条目记为 PS5

6. Given 书影音里已有相同豆瓣条目 ID 的条目
   When 导入到这条
   Then 用豆瓣数据覆盖条目信息和状态、评分、日期、短评；豆瓣没有的字段保留原值；条目的隐藏状态、已有封面（含游戏的 IGDB 封面）不变

7. Given 导入结束
   When 我看面板
   Then 显示汇总"新增 X、更新 Y、失败 Z"，失败的条目列出标题与原因；列表页刷新显示导入后的条目；读者页只触发一次重建

8. Given 导入中途出错（网络断开、豆瓣限流、我关掉了页面）
   When 我再次导入（全量或同步新标记）
   Then 没同步完的步骤从头再来，已经导入的条目按第 6 条覆盖，不会出现重复条目；中断那一步涉及的类别不会被记为"已同步"

11. Given 我完成过一次全量导入，之后在豆瓣新标记了 3 部电影、把 1 部"在看"的剧改成了"看过"
    When 我点"同步新标记"
    Then 同步时间按类别分别记录；每一步只从最新的标记往旧翻，翻到勾选类别上次同步时已有的标记就停（同一大类里两个类别的上次同步不同时，以较早的为准）；新增 3 部电影，那部剧改为"已完成"；面板显示"同步完成：新增 3、更新 1……"，几秒内结束

12. Given 某个勾选的类别还没有完整同步过（例如上次全量导入在书这一类中断了、上次没勾这个类别），或我换了一个豆瓣 ID
    When 我点"同步新标记"
    Then 这个类别所在大类的步骤按全量处理（同大类另一个类别的已有条目重复覆盖，无害），其他已同步过的大类仍只同步增量；完成后这个类别也有了同步时间

9. Given 我填的 ID 在豆瓣不存在 / 格式不对 / 标记不公开
   When 我点"全量导入"或"同步新标记"
   Then 分别提示"豆瓣上找不到这个用户""用户 ID 只能包含字母、数字、下划线、点和短横线""豆瓣标记未公开或需要登录，无法导入"，不写入任何条目

10. Given 导入进行中
    When 我想停下
    Then 可以点"停止"，已经导入的条目保留；停止后同样只触发一次重建

## 3. 约束与假设

**约束**:
- 只需要豆瓣用户 ID；不收集、不保存豆瓣密码或 Cookie
- 服务端只请求豆瓣白名单主机，不跟随跳转（同 US-02）
- 导入按页分批进行，每批耗时受 Worker 单次调用限制约束（Feature NFR）
- 增量只能发现标记时间晚于上次同步的标记：在豆瓣修改旧标记的评分 / 短评（若豆瓣不刷新标记时间）、删除标记、改为"想看"，增量都不会反映，需要时点"全量导入"（删除与改想看全量也不处理）

**假设**:
- 豆瓣移动端标记接口不登录可读公开标记（2026-10-23 spike 已验证，见 [Backlog](../../../../../../backlog/douban-bulk-import.md)"spike 结论"）
- 导入的游戏没有封面，由作者之后在编辑表单逐条粘贴 IGDB 链接
- 豆瓣标记列表按大类（影视 / 书 / 游戏）返回，不能按电影 / 剧集等类别筛选：只勾一个类别时仍要翻完这个大类的列表，只是跳过未勾选类别的标记；书只勾"书"或"漫画"之一时仍要请求每本书的标签来判定
- 豆瓣标记列表按标记时间倒序（2026-10-23 spike 已验证）；"在看"改"看过"时豆瓣刷新标记时间（未验证，见 Backlog"增量同步的已知限制"）
