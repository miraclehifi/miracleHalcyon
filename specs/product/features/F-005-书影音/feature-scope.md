# 书影音

**Feature ID**: F-005
**状态**: draft
**创建时间**: 2026-10-21

---

## 1. 概述

**一句话描述**: 作者在后台手动录入读过、看过、玩过以及正在进行的书影音条目，粘贴豆瓣分享链接即可自动填好条目信息；读者在 `/media` 按分类浏览。

**背景**:
路线图 F-005，整体参考 [pseudoyu · Media](https://www.pseudoyu.com/media?type=book)，从简。2026-10-19 作者改方案：不做豆瓣 RSS 同步、全量导入和 Cron，改为手动录入 + 链接识别（交互参考淘宝收货地址的"智能识别"）。需求与已确认的决策见 [Backlog](../../../backlog/media-douban-sync.md)。

**目标用户**:
- 作者（单管理员，已登录）：录入、编辑、隐藏、删除条目
- 读者（匿名访客）：浏览 `/media`

---

## 2. 范围

### In Scope（本次要做的）

- **分类**：书 / 漫画 / 电影 / 剧集 / 游戏 / 桌游（`book` / `comic` / `movie` / `series` / `game` / `boardgame`），共 6 个；动画剧集按剧集记，动画电影按电影记
- **状态**：只有"已完成"（读过 / 看过 / 玩过）和"进行中"（在读 / 在看 / 在玩）两种，按分类显示对应动词
- **读者页 `/media`**：分类 Tab 切换；页头显示当前分类数量与进行中数量；进行中的条目置顶，其余按标记日期倒序；书、漫画用卡片（`MediaCard`），其余分类用列表行（`MediaRow`），具体形态以 design-ui 为准；有豆瓣链接的条目链接到豆瓣页，没有的不可点击、不显示"豆瓣 ↗"；隐藏的条目不显示；替换当前的 404
- **后台条目列表**：按分类查看全部条目（含隐藏），可编辑、隐藏 / 取消隐藏、删除单个条目
- **后台录入 / 编辑表单**：分类、标题、封面、作者 / 导演 / 开发商、年份、豆瓣链接（来自识别，只读展示）；状态、我的评分（1–5，可空）、标记日期、短评（作者手动填）
- **豆瓣链接识别**：表单顶部识别框，粘贴纯链接或 App 分享的"文字 + 链接"，点"识别"后由服务端解析条目数据填入表单；只解析标题、封面、作者 / 导演 / 开发商、年份、分类、豆瓣链接与条目 ID，不解析状态、评分、日期、短评；部分识别、识别失败、重复条目的处理按 Backlog"识别交互"
- **按豆瓣条目 ID 去重**：识别到已录入的条目时提示，并提供"去编辑已有条目"；没有豆瓣链接的条目不参与去重
- **封面转存 R2**：识别时服务端带豆瓣 Referer 下载封面供表单预览，保存条目时存入 R2，读者端只访问 R2 地址；作者也可手动上传封面；条目删除或换封面时清理旧封面
- **触发重建**：新增、编辑、隐藏、删除条目后触发 Deploy Hook，重建读者页
- **后台顶栏导航**：新增"书影音"入口（`/admin/media`）
- **按豆瓣用户批量导入**（2026-10-23 增量 [douban-bulk-import](../../../backlog/douban-bulk-import.md)）：后台填豆瓣用户 ID，导入影视、书、游戏中已完成 / 进行中的标记（含状态、评分、标记日期、短评），可重复执行同步；相同豆瓣 ID 用豆瓣数据覆盖；游戏不下载豆瓣封面

### Out of Scope（本次不做的）

- 豆瓣 RSS 同步、豆列批量导入、定时任务（Cron）（"全量导入、个人标记页抓取"已由 2026-10-23 增量改为按用户 ID 导入）
- Steam / PS / Switch 同步
- 音乐分类
- "想看 / 想读 / 想玩"状态
- 条目详情页、年度统计
- 单条链接识别时解析状态、评分、标记日期、短评（批量导入会带上）
- 读者端搜索、筛选（除分类 Tab 外）

## 3. 边界定义

### 本 Feature 负责

- 书影音条目领域（新 Domain，命名在 design-arch 定，避开已有 `media` 图片领域）：D1 表、条目增删改查、豆瓣链接解析
- `/media` 读者页、`/admin/media` 后台列表与表单
- 条目封面的 R2 存储与清理

### 本 Feature 不负责

- 文章相关功能 → F-001 / F-002
- 文章图片的上传与清理 → F-001 / F-006

### 依赖的其他 Feature

| Feature | 依赖内容 | 说明 |
|---------|----------|------|
| F-001 | 后台会话、Origin 校验、`AdminHeader` | 沿用 |
| F-001 | Deploy Hook 重建（[add-deploy-hook-rebuild](../../../tasks/sprint-4/add-deploy-hook-rebuild.md)） | 复用触发方式 |
| F-001 | R2 绑定 `MEDIA` | 封面存储复用同一桶，key 前缀区分（design-arch 定） |
| F-002 | 读者外壳（顶栏 `/media` 入口、页脚、设计令牌） | 沿用 |

### 被依赖情况

无。

**反向影响**:
- **F-006 媒体存储清理**：书影音封面若与文章图片同桶，必须不被 F-006 判定为"未引用图片"而误删。F-006 只扫描 D1 `images` 表中的记录，封面若不写入 `images` 则不受影响——design-arch 必须确认
- **F-001 `AdminHeader`**：新增"书影音"导航项，admin.pen 顶栏同步
- **F-002 读者顶栏**：`/media` 由 404 变为真实页面，构建产物检查（`test:build`）需覆盖

## 5. 成功指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|----------|
| 录入成本 | 粘贴一个豆瓣书 / 电影 / 剧集 / 游戏链接，识别后只需补状态、评分、日期即可保存 | E2E（识别接口打桩）+ spike 实测真实链接 |
| 识别成功率 | spike 选取的书、漫画、电影、剧集（含动画剧集）、游戏、桌游样例链接中，标题与封面识别成功 ≥ 90% | spike 记录 |
| 识别降级 | 识别失败时表单可用、已填内容不丢失，可全部手填保存 | E2E |
| 读者页零外链图片 | `/media` 页面不请求任何豆瓣域名资源 | 构建产物检查 / E2E 网络请求 |
| 读者页性能 | `/media` 静态预渲染，无交互部分不加载 React；LCP < 2.5s | 构建产物检查、Lighthouse |

**已知风险**: Worker 出口 IP 可能被豆瓣拦截（plan-tasks 第一个做 spike）；被拦时识别降级为全部手填。
