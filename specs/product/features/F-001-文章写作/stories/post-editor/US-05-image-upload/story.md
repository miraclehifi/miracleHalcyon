# 图片上传

**US ID**: US-05
**所属分组**: post-editor
**状态**: draft

---

## 1. User Story

**作为** 作者
**我想要** 直接把截图粘贴或拖进正文
**以便于** 不用手动上传图片、复制链接

---

## 2. 验收标准

1. Given 我在正文编辑区
   When 我粘贴剪贴板中的图片，或拖入图片文件
   Then 光标处先插入占位，预览区立即显示该图片的半透明、微模糊缩略图卡片，卡片上显示当前阶段（"正在压缩…""正在上传… 75%"）和进度条；上传成功后卡片淡出，占位替换为 `![文件名](图片URL)`，预览区显示正式图片

2. Given 我点击工具栏"插入图片"
   When 我选择本地图片
   Then 行为同上

3. Given 图片超过 50MB（按压缩前的原始大小）
   When 我尝试上传
   Then 提示"图片不能超过 50MB"，不上传，不生成卡片

4. Given 文件不是 png/jpg/webp/gif（例如 svg、pdf）
   When 我尝试上传
   Then 提示"仅支持 png、jpg、webp、gif"，不上传，不生成卡片

5. Given 上传过程中网络失败或服务端返回错误
   When 上传失败
   Then 卡片保留并变为红框，显示失败原因（如"网络中断""上传失败，请重试"），提供"重试"和"移除"：重试从头重新处理并上传，成功后照常替换；移除则删掉源码中的占位；正文其他内容不受影响

6. Given 我一次拖入多张图片
   When 上传
   Then 每张图片各有一张卡片，进度和状态各自独立；完成后按拖入顺序各自插入引用

7. Given 我上传一张长边超过 2560px 或体积 ≥ 500KB 的 JPEG / WebP 照片
   When 上传
   Then 浏览器先压缩为长边不超过 2560px 的 WebP（浏览器不支持导出 WebP 时为 JPEG），去掉 EXIF / GPS，方向按 EXIF 转正；URL 中的宽高和主色与压缩后的文件一致

8. Given 我上传 PNG、GIF 或小图（长边 ≤ 2560px 且 < 500KB）
   When 上传
   Then PNG 只缩尺寸、仍为 PNG；GIF 和小图原样上传；压缩结果不比原图小、或压缩过程出错时，改用原图上传，不打断写作

9. Given 源码中有上传占位（处理中 / 上传中 / 上传失败），但它已没有对应的上传任务（例如页面刷新后、或撤销"移除"后恢复的占位）
   When 预览
   Then 卡片显示"上传已中断"，只提供"移除"（原文件已不在内存中，无法重试）

10. Given 已发布文章的正文中残留了上传占位
    When 读者打开文章页
    Then 占位不显示任何内容（不显示"图片上传中…"或失败卡片），文章其余部分正常

---

## 3. 约束与假设

**约束**:
- 图片存储于 R2，文件名使用随机/哈希命名，避免覆盖与路径猜测
- 上传接口需登录
- 压缩在浏览器完成，服务端不变（按魔数判定格式、以文件头解析宽高）；50MB 上限保留，作为压缩失败退回原图时的兜底
- 压缩阶段没有真实进度（按时间平滑推进），上传阶段为真实字节进度

**假设**:
- 并发上传数沿用 2；源码中的占位与插入顺序规则不变
