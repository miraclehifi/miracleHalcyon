## BH-01: 拖入安卓动态照片，插入一条实况照片引用

**SC-ID**: SC-LIVE-01

```gherkin
Given 我在写文章页，工具栏"实况照片"开关已开启，源码区光标在第 3 行行尾
  And "IMG20260516172228.jpg" 是 OPPO 动态照片（JPEG 内嵌 mp4，XMP 标注 MotionPhoto）
When 我拖入该文件
Then 光标处只出现一条占位文本
  And 上传完成后占位被替换为 "![IMG20260516172228](/img/{yyyy}/{mm}/{id}_{w}x{h}_{rgb}.jpg#live)"
  And R2 中有该 jpg 与同名 ".live.mp4" 两个文件
  And 预览区该图片左上角显示 "LIVE" 标记
```

## BH-03: 动态照片的两种 XMP 格式都能识别，静态图不含视频字节

**SC-ID**: SC-LIVE-03

```gherkin
Given "IMG20260516172228.jpg" 用 Motion Photo XMP（Item:Length）标注
  And "MVIMG_0002.jpg" 用旧版 MicroVideoOffset 标注
When 我分别拖入这两个文件
Then 内嵌视频都被切出，并与静态图在同一请求中上传
  And 上传的静态图不含内嵌视频字节
  And 源码插入的引用 URL 都带 "#live"
  And 上传的静态图按 US-05 BH-13 压缩
When 我拖入没有这类 XMP 的普通 JPEG
Then 按普通图片上传，引用不带 "#live"
```

## BH-04: 一批文件中混有动态照片与普通图片，各自按顺序插入

**SC-ID**: SC-LIVE-04

```gherkin
Given 我选中了 "a.png"、"IMG20260516172228.jpg"、"b.jpg" 三个文件
When 我一次拖入
Then 源码按 a、IMG20260516172228、b 的顺序插入三条引用
  And 只有 IMG20260516172228 的引用带 "#live"
```

## BH-05: 进度卡片依次显示压缩、处理实况视频、上传三个阶段

**SC-ID**: SC-LIVE-05

```gherkin
Given 实况开关已开启
When 我拖入动态照片 "IMG20260516172228.jpg"
Then 预览区卡片先显示 "正在压缩…"，进度在 0–15% 之间推进
  And 再显示 "正在处理实况视频…"，进度在 15–40% 之间推进，并出现 "仅转为静态图" 按钮
  And 再显示 "正在上传… N%"，N 从 40 增长到 100
  And 源码占位在处理阶段为 "![处理中…]()"，上传阶段为 "![上传中…]()"
  And 上传请求带上由压缩后静态图计算的主色与宽高
When 我拖入普通图片 "b.jpg"
Then 卡片跳过 "正在处理实况视频…"，上传阶段从 15% 开始
```

## BH-06: 视频处理后超过 10MB，退回为普通图片插入

**SC-ID**: SC-LIVE-06

```gherkin
Given 当前浏览器不支持 H.264 编码
  And "IMG20260516172228.jpg" 的内嵌视频只转封装后为 16.4MB
When 我拖入该文件
Then 只上传静态图
  And 源码插入的引用不带 "#live"
  And 显示提示 "实况视频超过 10MB，已作为普通图片插入"
```

## BH-08: 实况照片任一文件上传失败，两者都不保留

**SC-ID**: SC-LIVE-08

```gherkin
Given 上传接口对本次请求返回失败（或网络中断）
When 我拖入动态照片 "IMG_3000.jpg"
Then 源码占位变为 "![上传失败]()"，源码其他内容不变
  And R2 中不存在这次的图片或视频
  And 预览区卡片变为红框，显示失败原因，提供 "重试" 和 "移除"
When 接口恢复后我点击 "重试"
Then 重新切视频、转码并在同一请求中上传图片和视频，成功后插入带 "#live" 的引用
```

## BH-09: 浏览器不支持 H.264 转码，保留原编码并提示

**SC-ID**: SC-LIVE-09

```gherkin
Given 当前浏览器的 VideoEncoder 不支持 avc1
  And 动态照片 "IMG_4000.jpg" 内嵌 HEVC 视频，只转封装后 ≤ 10MB
When 我拖入该文件
Then 视频以 HEVC 编码封装为 mp4 后上传
  And 引用带 "#live"
  And 显示提示 "该实况视频在部分浏览器中只显示静态图"
```

## BH-10: 预览中桌面悬停 / 手机长按播放实况照片

**SC-ID**: SC-LIVE-10

```gherkin
Given 预览区有一张实况照片，显示静态图与 "LIVE" 标记
When 我在桌面把鼠标移到图片上
Then 视频静音播放一次，"LIVE" 标记变为播放中样式
When 我移出图片
Then 回到静态图
```

手机：长按图片播放，松手回到静态图；长按不触发系统图片菜单。

## BH-11: 预览中视频播放失败，退回静态图并隐藏 LIVE 标记

**SC-ID**: SC-LIVE-11

```gherkin
Given 预览区有一张实况照片，其视频在当前浏览器无法解码
When 视频加载出错（或 canPlayType 判定不支持）
Then 图片只显示静态图
  And 不显示 "LIVE" 标记，悬停不再尝试播放
```

## BH-12: 通过"插入图片"选择动态照片，同样识别

**SC-ID**: SC-LIVE-12

```gherkin
Given 我点击工具栏"插入图片"
When 我在文件选择器中选中 "IMG20260516172228.jpg"
Then 结果与拖入相同：只插入一条带 "#live" 的引用
```

## BH-14: 实况开关关闭（默认）时动态照片只上传静态图

**SC-ID**: SC-LIVE-14

```gherkin
Given 我第一次打开写文章页，工具栏 "实况照片" 开关显示为关闭
When 我拖入 OPPO 动态照片 "IMG20260516172228.jpg"
Then 卡片只经过 "正在压缩…" 和 "正在上传…"，不出现 "正在处理实况视频…"
  And 不加载视频处理组件（mediabunny）
  And 上传请求中只有静态图（不含内嵌视频字节，已压缩），R2 中没有 ".live.mp4"
  And 插入的引用为 "![IMG20260516172228](/img/….webp)"，不带 "#live"
```

## BH-15: 实况开关的选择记在本浏览器，读不到时按关闭

**SC-ID**: SC-LIVE-15

```gherkin
Given 我在写文章页打开了 "实况照片" 开关
When 我刷新页面，或打开另一篇文章的写文章页
Then 开关仍为开启
Given 浏览器禁止读写本地存储（读取抛出异常）
When 我打开写文章页
Then 开关显示为关闭，页面正常工作；切换开关在本次页面内仍然生效
```

## BH-16: 处理实况视频时点"仅转为静态图"，放弃本张视频

**SC-ID**: SC-LIVE-16

```gherkin
Given 实况开关已开启，我同时拖入动态照片 "IMG_A.jpg" 和 "IMG_B.jpg"
  And "IMG_A.jpg" 的卡片正显示 "正在处理实况视频…" 与 "仅转为静态图" 按钮
When 我点击 "IMG_A.jpg" 卡片上的 "仅转为静态图"
Then IMG_A 的视频处理被放弃，卡片直接进入 "正在上传…"
  And IMG_A 只上传静态图，引用不带 "#live"
  And IMG_B 仍按实况照片上传，引用带 "#live"
  And 工具栏 "实况照片" 开关保持开启
```

"仅转为静态图" 只在 "正在处理实况视频…" 阶段显示；普通图片、开关关闭时的卡片、以及进入上传阶段后都不显示。
