### 2. 部分覆盖（54 个）

主要结果都测了，缺少用例里列出的部分边界或变体：开放重定向变体、Origin 变体、篡改 Cookie、slug 与标题的边界值、分页与筛选组合、注入类输入、"失败后读回原值"等。逐条见 [traceability](traceability.md)"缺口明细"。

### 3. 验收文档与设计脱节

US-03、US-07 的部分用例写在 design-domain 之前，期望值后来被设计改掉了，但文档没有同步：空标题存为"无标题"（不是 400）、标题上限 200 / slug 上限 80（不是 120 / 100）、发布缺字段返回 422 `MISSING_FIELDS`（不是 400）、PUT 提交整份工作稿（缺字段 400）、slugify 先做 NFKD（Café → cafe）、slug 去首尾空白、标签补全按包含匹配（不是前缀）。US-06 的 TC-US06-24 写的是"保存完成后再等 2 秒"，实现是保存完成后立即再存。

### 4. 成因

Sprint 1 按"一个任务一个测试"组织，测试对应领域单元规格与接口契约（AUTH-UT、POST-UT、ED-UT），不对应验收用例，plan-tasks 时也没有做 TC → 任务的覆盖检查。Sprint 2 起任务带测试清单并在测试名中写 TC 编号，Sprint 2–4 的用例基本都有追溯。
