## 目标与验收

**目标**: 作者不必逐条粘贴链接，一次导入豆瓣上已有的全部标记；以后只同步新增标记，几秒完成。

**验收条件**:
- [ ] 后台书影音页有"从豆瓣导入"入口：填写豆瓣用户 ID（`douban.com/people/{id}/` 中的 id）；ID 保存在服务端，下次（换设备也一样）默认带出
- [ ] 类别选择：勾选项为本站 6 个分类 书 / 漫画 / 电影 / 剧集 / 游戏 / 桌游，默认全选；至少选一个；只写入勾选类别的条目，未勾选类别的标记跳过（不计失败、不下载封面、不改本站已有条目）
- [ ] 两种方式："全量导入"（翻完全部标记）与"同步新标记"（增量）；该 ID 完成过全量导入后，默认按钮为"同步新标记"，并显示上次同步时间
- [ ] 增量：每类从最新标记往旧翻，遇到早于上次同步水位的标记即停止；只处理水位之后（含同一秒）的标记
- [ ] 水位按 本站分类 × 标记状态 记录（如 电影·看过、剧集·看过）；只勾选电影时剧集的水位不动，之后再勾选剧集，剧集按全量补齐
- [ ] 水位只在某一类完整同步结束（全量翻完或增量到达水位）后才前移；中断、停止、出错时不前移，下次增量会重新覆盖这段
- [ ] 某类还没有水位（从没完整同步过，或换了 ID）时，"同步新标记"对该类按全量处理
- [ ] 导入范围：影视（按 `is_tv` 分到电影 / 剧）、书（含漫画判定）、游戏（含桌游判定），分类映射规则与单条识别一致
- [ ] 只导入"看过 / 读过 / 玩过"和"在看 / 在读 / 在玩"，跳过"想看 / 想读 / 想玩"
- [ ] 每个条目带上：条目数据（标题、封面、作者 / 导演 / 开发商、年份、豆瓣链接与 ID）+ 状态、评分（豆瓣 1–5 星，未评分为空）、标记日期、短评
- [ ] 封面由服务端带 Referer 下载并转存 R2（同单条识别）；单个封面失败不影响该条目导入，条目保存为无封面
- [ ] 已存在相同豆瓣 ID 的条目：用豆瓣数据覆盖条目字段与状态、评分、日期、短评；不改"隐藏"状态；封面已有时不重新下载
- [ ] 进度可见：显示"已处理 N / 总数"，结束后汇总"新增 X、更新 Y、跳过 Z（想看）、失败 W"，失败条目列出标题与原因
- [ ] 中途失败（网络、豆瓣限流）可再次导入，已导入的条目不会重复
- [ ] 豆瓣返回需登录 / 标记不公开时，提示"豆瓣标记未公开或需要登录，无法导入"
- [ ] 整次导入结束后只触发一次 Deploy Hook 重建读者页
- [ ] 不需要也不保存豆瓣密码或 Cookie

### 增量同步的已知限制（作者知悉）

- 在豆瓣上修改**旧**标记的评分或短评，如果豆瓣不刷新这条标记的时间，增量同步不会发现，需要偶尔点一次"全量导入"（豆瓣是否刷新标记时间未验证：会改作者账号数据，不做实验）
- 在看 → 看过：豆瓣会把它当作新的"看过"标记（预期标记时间刷新，出现在看过列表最前），增量会把本站条目从"进行中"改为"已完成"
- 豆瓣上删除的标记、改为"想看"的标记：全量和增量都不会删除本站条目（作者在后台手动删除或隐藏）

### spike 结论（2026-10-23，本机直连，用户 189806038）

| # | 假设 | 结果 |
|---|------|------|
| ① | 不登录可拉公开标记 | ✅ `GET https://m.douban.com/rexxar/api/v2/user/{uid}/interests?type={type}&status={status}&start=&count=`（`type` ∈ movie / book / game，`status` ∈ done / doing），带 `Referer: https://m.douban.com/` + 移动端 UA，全部 200 |
| ② | 数量 | 影视看过 614 / 在看 20；书读过 241 / 在读 18；游戏玩过 142 / 在玩 12 |
| ③ | 分页 | `count` 上限 50；单页实际返回可能少于 `count`（失效条目被过滤），翻页必须按 `start += count` 而不是返回条数；以 `total` 判断结束 |
| ④ | 状态参数 | 非法 `status` 会返回全部（含想看，total 1118）→ 请求只传 `done` / `doing`，且对返回的 `interest.status` 再过滤一次 |
| ⑤ | 标记字段 | `status`、`rating.value`（1–5，未评为 `null`）、`create_time`（`YYYY-MM-DD HH:mm:ss`）、`comment`、`is_private`、`platforms`（游戏：作者实际所玩平台，如 `PS5` / `PC` / `NS 2`） |
| ⑥ | 条目字段 | 影视：`type` = `movie` / `tv`（无 `is_tv`）、`year`、`directors`、`genres`、`cover_url`；书：`author`、`pubdate`（如 `2012-9-1`，无 `year`）、`cover_url`，标签为空 → 漫画判定仍需 `book/{id}/tags`；游戏：`release_date`、`genres`、`platforms`，无开发商 → 需 `game/{id}` |
| ⑦ | 限流 | 连续 12 次翻页请求无限流 |
| ⑧ | 错误 | 用户不存在 → 404 `traversal_error` |
| ⑨ | 排序 | 6 类列表均按 `create_time` 严格倒序（影视看过连续 12 页 235 条验证）→ 增量可按水位截断 |

### AI 设计决定（文档阶段按作者偏好直接定，待事后审阅）

- 每次导入请求只处理一页 20 条，后台页循环调用直到结束：子请求数最多 1（列表）+ 20（书 tags 或游戏详情）+ 20（封面）= 41，低于 Workers 免费版每次 50 的上限；进度可见、天然断点续导
- 游戏不下载豆瓣封面（[ADR-013](../engineering/features/F-005-书影音/architecture/adr/ADR-013-game-cover-igdb-link.md)：游戏封面只用 IGDB 链接）；导入的游戏无封面，作者之后逐条补 IGDB 链接；覆盖已有游戏时保留其 IGDB 封面
- 游戏平台：取标记里 `platforms` 第一个能映射的（`PS5`→`ps5`、`PS4`→`ps4`、`NS`→`switch`、`NS 2`→`switch2`、`PC`→`steam`）；都映射不上 → 新条目默认 `ps5`，已有条目保持原值
- 年份：影视用 `year`；书取 `pubdate` 首项开头 4 位；游戏取 `release_date` 开头 4 位
- 覆盖规则：豆瓣有值的字段覆盖；豆瓣缺失的字段（如游戏开发商请求失败）保留原值；`hidden`、已有封面不动
- 增量水位存 D1 新表 `shelf_import_state`（按 用户 ID × 类别 × 状态，值为豆瓣 `create_time` 原文）；用户 ID 也存在服务端，不再用浏览器 `localStorage`
- 用户 ID 校验 `^[A-Za-z0-9_.-]{1,64}$` 后放进路径（防路径注入）；请求主机固定 `m.douban.com`，沿用 `douban/` 白名单与 `redirect: 'manual'`
