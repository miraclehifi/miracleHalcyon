## 目标与验收

**目标**: 作者在豆瓣上的标记自动同步到站内，读者在 `/media` 按分类浏览作者读过、看过、玩过以及正在读 / 看 / 玩的条目。

**业务价值**: 作品集的一部分，展示作者的阅读和娱乐口味；不需要手动维护，在豆瓣上标记即可。

**验收条件**:
- [ ] 分类共 7 个：书 / 漫画 / 电影 / 剧 / 动画 / 游戏 / 桌游（book / comic / movie / series / anime / game / boardgame）；不做音乐
- [ ] 只导入"看过 / 读过 / 玩过"和"在看 / 在读 / 在玩"，跳过"想看"类
- [ ] 首次全量导入历史数据，之后通过豆瓣 RSS 增量同步；状态从"在看"变为"看过"时随之更新
- [ ] `/media` 用 Tab 切换分类；每行显示：封面、标题、作者 / 导演 / 开发商、我的评分；正在进行（在读 / 在看 / 在玩）的条目加在看标记；按标记时间倒序；条目链接到豆瓣页
- [ ] 后台：立即同步按钮 + 每天一次 Cron；可以隐藏、删除单个条目，可以修改条目分类
- [ ] 同步有变更时触发 Deploy Hook，重建读者页

## 备注

### 作者决定（2026-10-15）

| 事项 | 决定 |
|------|------|
| 数据来源 | 只用豆瓣。不做 Steam / PS / Switch 同步，不做手动录入 |
| 分类映射 | 剧 / 动画：豆瓣"电视剧"条目中，类型含"动画"的归动画，其余归剧；动画电影归电影。漫画：豆瓣"书"条目中带"漫画"标签的归漫画。桌游：豆瓣"游戏"条目按平台 / 类型字段识别（字段待 spike 确认）。自动规则判断错时，在后台手动改分类，手动改过的分类同步时不覆盖 |
| 封面 | 所有条目都显示封面（曾考虑只给正在进行的条目显示，最终改为全部显示）。用方案 A：直接引用豆瓣 CDN 地址，`<img referrerpolicy="no-referrer">`，不转存，服务器成本为 0。风险：豆瓣改防盗链规则后封面会集体失效，到时改为同步时转存 R2（方案 C），图片加载失败时要有占位 |
| 删除同步 | RSS 不会推送"取消标记"，在豆瓣上删掉的标记需要在后台手动删除 |
| 页面形态 | 参考 pseudoyu：分类 Tab + 列表，不做条目详情页和年度统计 |

### 技术风险（plan-tasks 时第一个做 spike）

- 豆瓣官方 API 已于 2018 年关闭。全量导入依赖非官方的 Frodo 接口，增量依赖个人 RSS `douban.com/feed/people/{id}/interests`，两者都可能失效
- Cloudflare Worker 的出口 IP 可能被豆瓣拦截。如果被拦，全量导入改成本地脚本（导入 D1），增量方案再评估
- spike 还要确认：RSS 能否拿到评分、状态、标记时间；漫画标签和桌游字段能否识别；`no-referrer` 下封面能否正常显示

### 拆分建议

两个 US：
1. 展示页 + 后台条目管理（隐藏 / 删除 / 改分类）
2. 豆瓣全量导入 + RSS 增量同步 + Cron + 触发重建（含 spike）

### 讨论记录

- 最初考虑同步 Steam / PS / Switch：Steam 有官方 Web API；PS 用非官方 psn-api，令牌几周就过期；Switch 只能用逆向的 nxapi，风险最高。作者最终决定只用豆瓣
- 封面比较过四种方式：A 直接引用、B Worker 代理、C 同步时转存 R2、D 构建时下载。成本都接近 0，A 最省事但最不稳，先用 A
