# ADR-005: 自描述图片 URL 与 GFM 兼容扩展写法

## 状态
Accepted（2026-10-12）

## 背景
`ArticleImage` 需要原图宽高来预留比例，组图网格（ChromaGrid）需要主色，还要支持实况照片、宽图、组图（article-image-display Backlog）。产品约束是只支持 GFM，渲染模块要在浏览器和 Worker 两端运行（ADR-001），最好不查数据库。

## 决策
- R2 key：`img/{yyyy}/{mm}/{id}_{w}x{h}_{rrggbb}.{ext}`。id 为 10 位随机 base32；宽高由服务端从文件头解析，主色由上传时的浏览器计算（服务端校验格式）。
- 实况视频：与图片同名，扩展名为 `.live.mp4`。
- Markdown 写法（全部是合法 GFM，在其他阅读器里退化为普通图片）：

| 效果 | 写法 |
|------|------|
| 图注 | `![alt](url "图注")`（title） |
| 宽图 | URL 片段 `#wide` |
| 实况照片 | URL 片段 `#live` |
| 多个标记 | `#live,wide` |
| 组图（网格） | 一个段落里只有 ≥ 2 张图片（用换行分隔，不空行） |
| 组图（手风琴） | 组内第一张图带 `#accordion` |

- 渲染插件从文件名解析宽高与主色，从片段解析标记。解析失败时按普通 `<img>` 输出，不报错。
- `images` 表只做记录，渲染不依赖它。

## 后果
- 正面：渲染无副作用、可同构；源码可读；兼容外链图片（外链图片没有宽高，就不预留比例）。
- 负面：文件名不能改；作者手写时需要了解写法，由预览图片菜单（US-12）辅助。
