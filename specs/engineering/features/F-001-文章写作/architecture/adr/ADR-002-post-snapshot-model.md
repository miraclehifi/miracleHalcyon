# ADR-002: 文章"工作稿 + 已发布快照"模型

## 状态
Accepted（2026-10-12）

## 背景
需求有三条：自动保存不得改变读者看到的内容（US-06-6）；读者永远读不到草稿或未发布修改（US-08 约束）；列表要显示"已发布 · 有未发布修改"。范围外不做版本历史。

## 决策
- 一篇文章对应 `posts` 表中的一行，包含两组字段：
  - 工作稿：title、slug、tags、summary、body、published_at（发布日期）、updated_at
  - 已发布快照：`pub_*` 同名字段 + published_at
- 自动保存只写工作稿。发布 / 发布更新 = 把工作稿复制到快照。撤回 = 清空快照（工作稿保留）。
- `status`：快照为空时是 `draft`，否则是 `published`。"有未发布修改" = 已发布 且 contentHash(工作稿) ≠ contentHash(快照)。（2026-10-13 design-domain 细化：原定按时间比较，改为按内容哈希，避免"保存了相同内容"或"发布前的 flush 保存"被误判为有修改；见 post/domain-model.md §2）
- slug 唯一性同时检查其他文章的工作稿 slug 和快照 slug，避免发布更新时撞上别人已公开的地址。
- F-002 只通过 `published-query.ts` 读取 `pub_*` 字段。

## 后果
- 正面：不需要第二张表，也不需要 join；"读不到草稿"由结构保证。
- 负面：字段数量翻倍；不支持多个历史版本（符合范围）。
